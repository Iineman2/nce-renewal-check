# Feature 1.2 Principle 5: Finding a case should require the least necessary effort

An operator can load the supplied normalized Pax8 CSV alone, search familiar descriptions, narrow by account/customer/product/inclusive renewal dates, distinguish cases and explicitly carry one exact source ID into inspectable Current case evidence. No ID memorization or manual copying is required. The optional exact-ID shortcut still uses the same parser/selector/comparison path.

Search uses all whitespace-separated literal tokens across subscription/account/customer reference/name, product family/name/SKU, seats, commitment and renewal date. Descriptive discovery is case-insensitive; exact account filtering and identity remain case-sensitive. Unicode is not accent/confusable folded. Input limits are160characters for query/customer/product and128for account, with no invisible/control characters. Invalid/reversed dates are a visible recoverable filter error; active date ranges explicitly count excluded missing/invalid dates. Empty search results and malformed/unreadable sources have different recovery states.

Results stay in source order, show exact total and20rows per page, and expose account, customer, product, SKU, seats, term, renewal and logical record number. Singletons appear directly, but choosing is explicit. Global duplicate-ID counts are never recomputed from the filtered subset. Duplicate or unusable IDs cannot be chosen; missing account/customer/date may be inspected through the canonical unresolved projection but cannot be confirmed. Descriptions do not establish identity or linkage.

Private finder ownership binds parsed source and summaries. Both search projections and chosen-record projections are independently re-derived privately. Source/file/control/selector/answer/date/policy changes, discovery edits/paging, cancellation, reset/history and corruption invalidate prior selection/confirmation. Enter in discovery fields performs search without submitting record comparison. Native buttons and controls remain keyboard accessible; focus follows explicit selection, page changes and file errors.

GatesP5-01 through16 are named model contracts in case-finder.test.mjs. Gates17 through23 cover live search/selection invalidation, comparison integration, pagination/stale controls, keyboard, file lifecycle and filter/error recovery in ui-case-finder.js; gate24 is bounded browser/axe/reflow evidence and25is injected canonical projection failure. Gate26requires representative real-operator efficiency/comprehension; gate27requires native vendor-export/source acceptance. Both remain external pending.

Repeatable acceptance is output/one-case-principle-5/qc.py verify. It requires all prior regression inventories, actual current unit/browser/syntax receipts, prescribed finder assertions, complete hashed artifact index, executed resource payload/screenshot identity, negative results and actual final independent review. Preconditions validation for negative baselines explicitly relaxes the negative report's own completeness and later final-review phase; it never reports final acceptance. Negative report and final-phase metadata semantic predicates are separately tested. Final verification requires complete real final-review signoff. Prior evidence is preserved as historical, not reused as current acceptance.

Local synthetic operator paths do not certify unauthenticated vendor data, universal devices, assistive technologies, or real user speed/comprehension. No provider, upload, persistence or financial authority is introduced.
