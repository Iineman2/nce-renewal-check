# Principle 7 external acceptance protocol

Status: pending; no real vendor exports or MSP user sessions are available. This file defines finite acceptance work, not a request for indefinite interviews. Local automated success cannot mark these gates passing.

## Real evidence and original-system access

For one authorized MSP/customer/subscription, retain the actual Pax8 and HaloPSA export field definitions, export timestamps, original subscription/line/customer identities, active billing state and scheduled renewal setting. Record which fields map to the normalized schema, cannot map, or need manual confirmation. Do not remove legitimate multi-line billing just to create a one-row fixture. Do not include real secrets or signed contracts in synthetic test artifacts.

Run the result/repair paths using exact normalized claims traceable to those originals. Confirm source wording is usable for that tenant, role and locale; test no-access, incomplete export, contradictory originals and unreachable signed order. An authorized customer/operator must independently verify identity and freshness. A successful local rerun is not proof of vendor authenticity, contractual terms or a safe action cutoff.

Acceptance: each supported cause is traceable to its original field and usable next step; unsupported mapping or inaccessible evidence results in an explicit unresolved stop. Record any mismatch as a defect; repair it and rerun the affected case before acceptance.

## Task-based comprehension and keyboard session

Have an MSP operator perform an unknown-answer check, an outside-scope correction, a wrong-file repair, duplicate/link review, two-conflict review, an unavailable-agreement stop and a provisional positive result. Ask them to identify the decisive issue, original source, next action, expected rerun outcome and what the result does not authorize. Record actual actions and explanations rather than supplying the answer.

Acceptance: every task can be completed or deliberately stopped without founder intervention; no participant treats file acceptance as authentication or scope fit as financial/contractual approval. A critical misunderstanding blocks that task until copy/flow is fixed and retested. Keyboard-only checks must reach the same repairs, keep visible focus after cancel/reset/rerender and avoid hidden or trapped controls. Time-to-complete observations may be recorded; no unsupported speed threshold is claimed.

## Screen reader and browser/device coverage

Record browser/version, OS, assistive technology and mode. Test result announcements, first-action discovery, conflict state/pressed announcements, direct edits, file errors, cancelled reads, agreement rerenders, owner policy stop and unavailable-source guidance. At minimum cover the actual user's screen reader/browser combination, enlarged text/reflow and visible focus. Automated axe results do not substitute for these sessions.

Acceptance: source, blocker, action and expected outcome are intelligible; focus/announcements follow the user action; no critical keyboard or screen-reader failure remains. Record each tested state and any untested platform. Do not infer universal browser compatibility from one engine or simulated missing-API test.

## Separate downstream boundaries

Signed-clause interpretation, actual exposure, authenticated live records, financial deadlines, willingness to pay and adoption are separate product/market gates. Principle 7 provides an honest next evidence step or stop; it does not complete those capabilities.
