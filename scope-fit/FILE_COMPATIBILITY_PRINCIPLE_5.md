# Feature 1.3 Principle 5: authorized handling

Expected behavior defined 7 October 2026. Selecting a native file authorizes only the exact current role/File occurrence, this page, and immutable `local-selection-v2` policy. It authorizes local finding (Pax8), checking supplied record facts and inspecting the unchanged original. It grants no source authenticity, verified case identity, eligibility or financial authority.

1. All three UI reads use the one private handling session. Missing permission, a different File with equal name/bytes, wrong role, undeclared operation, source recipient mismatch, cloned state or another page cannot authorize admission. A delivered owned change, including same-object reselection, creates a new occurrence. Unchanged picker cancel retains its occurrence and starts no work. Empty dismissal revokes the affected role; a cancel event never grants access. An observed mismatch or getter failure retires the captured occurrence permanently, including after exact File restoration; a stale callback cannot revoke a newer occurrence. Permits are never serialized into source data or Worker packets.
2. The bounded job owner checks current permission at admission, processing yields, packet validation, native custody adoption and publication. Every original projection, raw-text consumption and binary recovery checks the bound permit. Revoked original/finder capabilities and detached controls cannot become live again.
3. No selected file, metadata, cell, derivative or diagnostic is uploaded, remotely processed, logged, persisted, copied to a clipboard or shared through application channels. Fixed application assets and local native module Workers are the declared recipients. No queue, remote fallback, OCR, agreement reader, service worker, tenant or cloud storage is enabled.
4. Retention is temporary while selected in this page, including while its tab is hidden. Cancel terminates the current task and invalidates derived case decisions while retaining selected files, current independent originals and retry permission. Cancel is not deletion. A detected local calendar date change clears files and requires reselection; suspended scheduling is not a guaranteed midnight timer.
5. Replacement, removal and a delivered same-object change immediately revoke the affected occurrence, stop its pending work and release its retained originals/cache. Existing dependent case/result/confirmation owners invalidate their state. The unchanged independent role remains inspectable.
6. Reset, native form reset, pagehide and persisted pageshow revoke permission and clear native picker values, filters, user facts, app-owned finder/case/results, caches and originals before presentation/runtime guards. Independent cleanup phases continue despite a damaged view. Captured native clearing falls back independently for persistent instance replaceChildren failures on original-evidence-sources, record-info, record-result, finder-results and case-subject, including each pair. Failure of every captured native primitive remains a host boundary. Boot never inherits browser-restored file permission. Fresh selection is required after restoration.
7. Private noncancelable native Blob/crypto work may retain bounded job references and reservations until settlement. It cannot expose bytes, admit the same occupied slot, renew permission or publish after revocation. Failed native termination halts admission. This is access/reference removal; no physical memory/disk erasure or browser/OS deletion is claimed.
8. Saving an original requires an explicit current action. Recovery produces exact original bytes as an owned opaque binary download with a generated role/digest name and an immediately revoked local URL. If release throws, the URL remains tracked, further recovery is quarantined, and independent reset cleanup continues. A later cleanup may retry only that existing URL; it grants no new access. Browser registry failure is not a successful deletion receipt. Reset does not delete the user's source, downloads, backups, browser caches or OS copies. There is no hosted deletion confirmation.
9. The immutable declaration appears in the existing separate File guide glossary before selection. Controls gain no subtitle, narrative, expandable text or permission checkbox. Only the exact canonical declaration from file-handling-policy.mjs is accepted. A missing/changed/foreign declaration or same-version prose/schema clone fails closed before dependent processing. Trusted source acquisition primitives remain internal Worker/Node mechanisms, not UI selection grants.

The lifetime owner's managed handles are limited to two per role (current view plus unpublished replacement); release callbacks remove history. Existing two active jobs, no queue, two global caches, byte/structure/time limits remain unchanged. Raw library calls and malicious trusted app code/extensions are outside the UI permission boundary; they cannot be claimed as untrusted evidence routes.

## Failure families and required gates

| Boundary | Required coverage |
| --- | --- |
| Permission | No selection; empty/fake File; wrong role/source/operation; same name/hash/time; same-object reselection; different owner/page; JSON clone; policy immutability; no Worker permit fields. |
| Processing | Permission changes after admission, during packet/byte/hash/row publication, after completion before view commit; cancellation; reset; late resolve/reject; old callback; native termination failure; reservation quarantine; retry. |
| Consumption | Current text/projection/byte recovery; role mismatch; old handle after replace/remove/reset; restored old handle; detached save/paging/finder/confirmation actions; finite handle turnover. |
| Removal | Both roles; independent role retained; hidden controls/info page; minimized viewport; changed glossary; view cleanup throws; canceled native form-reset event; duplicate/replaced picker; pagehide; persisted pageshow; real reload/navigation; hidden-tab retention. |
| Recipients | Main/Worker network, headers/body/query; storage/cookie/IDB/cache/service worker/filesystem; clipboard; console; BroadcastChannel/other tab; fixed assets only; actual native Workers; observer positive controls. |
| Presentation | Exact guide declaration; separate controls/info; no new button/body/subtitle; keyboard/focus; mobile320/375; zoom; axe; generated original download name/type/bytes/revocation. |
| Regression/proof | All historical named models retained; original/data-only/resource/transport/native-held gates; all11 UI regression fixtures; fresh isolated sessions, sequential timing; actual source/fixture/server/receipt/HTTP identities; immutable prior proof leaves; strict receipt parser and negative proof controls. |

Qualification and finite coverage belong to the new Principle5 proof/report owner. This specification is not proof of a pass, universal device/OS erasure, actual BFCache usage, production/native vendor exports or future cloud processing. Pagehide delivery can be skipped by OS process termination; fresh boot and persisted restoration fence new application access ([pagehide](https://developer.mozilla.org/en-US/docs/Web/API/Window/pagehide_event), [pageshow](https://developer.mozilla.org/en-US/docs/Web/API/Window/pageshow_event)). Recovery URL release follows the browser's [revokeObjectURL](https://developer.mozilla.org/en-US/docs/Web/API/URL/revokeObjectURL_static) contract.

Current closure evidence belongs to `../output/file-compatibility-principle-5-closure/REPORT.md`. Earlier P5 sealed outputs retain their original sources and verdicts. Full request headers, exact recovery deltas, independent diagnostics and reached recipient controls are required; unavailable APIs and finite observation horizons are recorded explicitly.
