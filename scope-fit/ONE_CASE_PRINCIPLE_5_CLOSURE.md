# Principle 5: expanded QC contract

Feature 1.2 lets a person find an inspectable case from a supplied normalized Pax8 CSV without supplying HaloPSA or knowing an exact subscription ID. Discovery does not authenticate a source, confirm a case, establish eligibility or grant authority to act.

Every rendered discovery generation belongs to one parsed source, one complete set of six filters, their current DOM control identities and their native date validity. Discovery targets and the rendered card projection are also bound; replacing a target during a read or altering a rendered projection invalidates it. A normal edit removes derived confirmation and rerenders against the same source. A silent value or control replacement invalidates discovery before selection, source confirmation, downstream confirmation, focus, visible-page activation or the freshness callback can reuse it. Native change, keyup and blur acknowledge edits that do not emit input; unchanged events are idempotent. An unfinished native date must show a repairable search error, clear derived authority and block manual comparison until corrected or cleared.

Search is literal default-lowercase substring matching. Query tokens use AND across one row's supported recognition fields. Exact account filters preserve case and leading zeros. Optional customer and product filters use literal substrings. Dates are inclusive Gregorian years 0001–9999; year 0000 rejects. Omitted filter members are empty, but explicit null or undefined members reject. Unpaired Unicode surrogates reject; evidence retains original cells and logical source positions. These changes supersede the historical null and Date.UTC behavior described in the audit.

All duplicates remain blocked across the complete file, including duplicates hidden by filters. A unique usable subscription identifier permits inspection; missing account, customer or occurrence facts still block source confirmation. Paging exposes at most 20 rows and never selects automatically. Navigation appears before long card lists. Source-only confirmation and joint downstream attestation remain distinct.

Supported source limits remain 2,000,000 UTF-8 bytes, 5,000 records, 64 columns and 1,024 code units per cell. These maxima cannot all be multiplied together within the byte budget. Separate boundary fixtures and a legal composite fixture exercise these limits. Local resource measurements are single Node/Chromium profiles and include their stated scope. They do not establish universal device latency, P95, peak memory or GC guarantees.

The immutable audit contains 334 conditions. The closure ledger assigns evidence owners; a lane or assertion name is not a passing receipt. Expanded acceptance requires 87 completed model assertions,112 browser assertions in their prescribed receipts and42 verifier scenarios linked to the fixed fault/check inventory, correct source and artifact bindings, exact rejection reasons and independent final review. The current verifier rejects unexecuted local assertions; negative baseline checks permit only the verifier report's own bootstrap phase to remain pending. The prescribed semantic mutation vectors cover current required predicates, rather than arbitrary future fields or every type/transition Cartesian product. Historical packs remain historical after source changes.

External evidence remains pending for human comprehension and effort, native export preparation, authenticated sources, real screen readers, hardware and engines not exercised, actual BFCache or process suspension, financial outcomes and agreements. Decoded text cannot prove original encoding provenance, recover identifiers already lost upstream, authenticate device time or withstand replacement of the entire trusted application. Documentation of these boundaries is not empirical acceptance of them.
