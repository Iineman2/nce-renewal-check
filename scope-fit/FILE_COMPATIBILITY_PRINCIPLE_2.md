## Meaning of original and derivative

The original is a private defensive copy of the exact bytes returned by the admitted native File acquisition. It includes initial BOM bytes, every delimiter, quote, whitespace character, line ending and trailing terminator. It is captured before asynchronous hashing or decoding. Re-encoding decoded text is never a substitute for this original.

Content identity is the pair `{sha256: SHA256(original bytes only), byteLength}`. Equal bytes have equal content identity; filenames, MIME types and timestamps establish none. Each acquisition still has a distinct opaque live source handle, bound to its supplied File occurrence and declared role. Equal content never restores a revoked handle or grants case confirmation. Content identity is not vendor authenticity, freshness, signed applicability or authority to act.

Decoding is a separate UTF-8 derivative. Its full text retains an initial BOM for source-coordinate fidelity. The native File.text comparison uses the decoder's one-initial-BOM treatment explicitly; no other character or line-ending transformation occurs. Invalid UTF-8 has no invented decoded derivative. Legacy text-only model inputs remain explicitly text-only evidence and cannot attest original file bytes.

## Exact source locations

The sole CSV scanner records original column positions and lexical slices. A cell projection includes its one-based column position, original header, exact quoted/unquoted lexeme (including accepted post-quote whitespace), decoded raw value, trimmed normalized value, and half-open UTF-16 and UTF-8 byte ranges. Header cells have their own locators. Byte ranges include the original BOM and measure bytes, rather than code units. Supplementary characters never yield a locator inside a surrogate pair.

Records retain exact text, their terminator separately, lexical source-record ordinal and the existing data-record number. Data-record numbers still exclude the header and completely empty records; they are not physical line numbers. Completely empty record runs are explicitly counted and source-linked compactly. EOF after a final terminator creates no extra supplied record. The original remains recoverable even where a display uses escaped characters or a bounded preview.

Blank, duplicate and normalization-colliding headers stay ordered positional evidence. They never become a merging keyed object or a successful normalized profile. Malformed CSV retains the captured original and a known failure location; any inspected prefix is explicitly partial and cannot become selectable rows or a whole-file success.

## Ownership and lifecycle

`file-evidence.mjs` owns private byte custody, content identity, live handles, defensive copies and bounded source projections. `runtime.mjs` owns the existing acquisition/deadline/profile path. `csv-evidence.mjs` is the single lexical scanner consumed by `preflight.mjs`; preflight continues to own normalized rows, case identity, selection, confirmation and comparison decisions. Parser provenance survives the existing selected-record projection and traces both Pax8 and HaloPSA contributors. No second case or compatibility authority is introduced.

All three application reads use the same byte-owning runtime path. `readLocalEvidence` returns full BOM-preserving text with its live original handle and any input problem. `readLocalFile` is only its wrapper: it removes exactly one initial BOM from its returned text, preserves existing exceptions, and releases its temporary handle. An intact independently read source remains inspectable if the other source fails.

The byte fulfillment copies the observed buffer before waiting for its sibling text read. Missing files, invalid size, size disagreement, byte acquisition rejection, sibling text-read rejection, deadline expiry, missing/rejecting/nonconforming SHA-256 and decoder-runtime faults produce no verified live handle. Failed or malformed hashing and decoder runtime are technical stops. Valid admitted bytes with a text/byte disagreement retain a verified original and byte-derived preview, with a clear input problem and no compatibility success. Invalid encoding retains a verified original without decoded text. Lexical/profile failures retain the original and bounded rejected or partial positional evidence. No failed path grants case authority.

Ordinary native text/byte IO rejection is an input-repair result with no successful original receipt. A broken acquisition/hash/decoder runtime is a typed terminal fault. A later comparison or source-selection validation failure retains its existing recoverable technical-stop path, with no case/financial authority; any independently verified original can still be inspected. This distinction is owned by acquisition errors, never guessed from exception prose. DOM/render integrity faults remain terminal.

The application exposes separate local evidence disclosures for Pax8 and HaloPSA, containing content identity, role, byte length, derivative limitations, bounded positional preview and an explicit Save original copy action. Saving returns the captured bytes as inert binary data; it never repairs or rewrites them. Original filename metadata is shown escaped; a safe binary download filename is a display choice only. No original or derivative is uploaded, persisted in browser storage, logged or executed.

An original source handle establishes fidelity only. Existing case/receipt/control/date/serial owners still decide what is current and actionable. Subscription ID, questionnaire, agreement, next-term and input-date edits retain originals whose native File occurrence is unchanged, while revoking dependent case confirmation. A role's file replacement or removal revokes that role's handle; the other role's unchanged original remains. Cancel or supersession retains originals already committed before that action, revokes unpublished results, and prevents pending reads/hashes from publishing. A new committed acquisition replaces and revokes its previous same-role handle even if bytes match. Explicit clear, native reset, history restoration, expired questionnaire reinitialization and terminal faults revoke all source bindings. Late byte reads or hashing cannot publish after their existing serial/control fence is lost. Source labels, locators, previews and recovery controls must agree with their private owner before use and after commit/focus. Cloned, serialized, wrong-role, revoked and forged handles or acquisition outcomes are rejected. Exact plain-data projection copies are accepted only when independently verified against the current live handle; changed fields, extra keys (including undefined) and absent fields fail. Comparison locations additionally resolve through the existing parser against the current source text, selected contributor and column positions before display.

3. Rejected blank/duplicate headers, malformed final/unselected records and invalid UTF-8 remain inspectable or recoverable to their actual acquisition extent, with no compatibility or case-authority promotion.
4. Defensive byte copies, bounded immutable projections and strict live-handle checks. No large inventory or typed buffer enters ordinary decision capture's bounded plain-data tree.
5. Existing byte/row/column/cell limits and large empty runs remain supported. A single-pass coordinate map avoids repeated prefix encoding. Full preemption, actual native-work cancellation and peak-memory/device qualification remain principle 3 work.
6. Actual browser recovery downloads match supplied bytes. Keyboard, mobile reflow, automated accessibility, inert hostile text, DOM/projection faults, source/case edits, cancel, replacement, reset, history and delayed hash/read completions pass.
   Same-name/different-byte files have distinct content identities; equal-byte/different-occurrence files never transfer confirmation. Missing, rejecting, malformed and nonconforming hash runtimes are explicit gates. Network, storage and content logging stay absent; failed/canceled recovery clears transient object URLs. Preview pages contain at most five retained records and can reach every retained record. Empty runs have bounded previews and counted full-file coverage, without pretending omitted display material was shown.
7. All existing exact model/browser contracts run fresh. ## Closure of the failure audit

The current comparison must match a complete canonical decision reconstructed by the existing comparison owner from the current captured plain-data input. Genuine raw cells and locators alone cannot justify a changed interpreted value, effective value, resolution, contributor, classification, issue, caveat or next action. Successful comparison capture requires current input; the privately issued source-free input-repair/technical-error result is the only input-free lane. Added source claims, handoffs, clones, accessors and modified failure objects cannot use that lane. Canonical case selection and financial fences retain their existing owners.

UTF-8 scalar validity is checked independently against the original bytes before actual decoding. Invalid original bytes retain exact recovery without an invented derivative. A decoder that passes startup samples but throws or returns false text for valid actual bytes is a technical runtime fault, including Error, TypeError and non-Error throws. Foreign dependency messages never become source diagnostics. This byte-validity check does not infer vendor authenticity or identify arbitrary legacy encodings.

The active screen view requires disclosed text to have cumulative ancestor opacity at least0.9, font size at least12 CSS pixels, readable line boxes and resolved foreground/background contrast at least4.5:1 (3:1 for large text). Image/gradient/text-fill substitution, horizontal displacement and unavailable pointer interaction fail closed. Three points per viewport-intersecting text-run rectangle are hit-tested when its visible intersection contains at least one complete CSS pixel in both dimensions. Subpixel edge slivers remain reachable by scrolling and are excluded from hit-testing to avoid viewport rounding. Opaque positioned covers are evaluated in their actual stacking contexts and with cumulative opacity; transparent or behind-source geometry alone cannot stop the view. Closed native disclosures and vertical scrolling remain supported. Native resize monitoring rechecks synchronously when observable metrics return. A viewport with at most1 CSS pixel in either dimension has no qualified screen presentation: automatic viewport checks await real metrics and then revalidate; byte custody remains intact. Publication and direct actions still validate immediately and cannot use that unobservable view. These finite screen checks do not certify every pixel, arbitrary CSS/compositing, print output or human readability.

Save and paging use privately owned onclick property handlers checked with their exact rendering contract. Removal of unrelated registered listeners cannot remove the owned action; lost/replaced handlers and observed dispatch suppression stop current results and revoke source handles. An independent observer checks completion in the next task because native event delivery can checkpoint microtasks between callbacks. Earlier suppression before that observer, removal of every observer, compromised hosts and silent native browser/OS write refusal remain outside this acknowledgement. The interface explicitly asks the operator to confirm the completed browser download. A successful browser download is checked byte-for-byte in qualification. Paging preserves unchanged source disclosure state and restores keyboard focus; disconnected prior controls cannot navigate a current binding. Long display filenames and surrogate-sensitive excerpts are bounded while original bytes remain complete.

Decoded UTF16 must consist of Unicode scalars before the original UTF8 roundtrip is accepted. A substituted decoder that returns an unpaired high or low surrogate is a terminal runtime integrity fault; native TextEncoder replacement must not hide false text behind genuine U+FFFD bytes. No evidence handle is issued for that text. Genuine U+FFFD and valid surrogate pairs remain supported, with original bytes unchanged.

Decoded text cannot have more UTF16 code units than the original UTF8 bytes. Reject oversized output before the scalar walk or re-encoding; these owned operations remain bounded by admitted input. Allocation or execution inside a faulty synchronous decoder itself is not preempted.
