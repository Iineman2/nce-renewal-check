# Principle 7: Correction must be easy and internally consistent

## Expected behavior

Change case is an explicit keyboard-accessible action. It revokes source confirmation, cancels current reads/discovery, clears the active source subject, link confirmation, comparison, conflict resolutions, ID and record-specific renewal-term/agreement answers together. Files remain available for reuse. Focus returns to the subscription field and an explanation states that a fresh check and confirmation are required.

Changing an established subscription ID, choosing a different finder candidate or replacing the source file also clears record-specific term/agreement assertions. Initial entry has no old case to clear. Comparing the same selected case again retains explicitly supplied answers, but always requires fresh confirmation. A billing-file replacement invalidates comparison/link/source authority; it does not change the source subject's term/agreement assertions.

Questionnaire answers remain visible operator assertions, not facts inferred from a selected row. Correction removes any rendered fit result that incorporated cleared agreement information; operators must review case-specific questionnaire answers and check fit again if they change. No old result is a verdict about a new case.

Pending reads use the existing invalidation generation. A late success, rejection or finally callback may not recreate a subject/result or alter the current request's controls. Detached source/finder/result callbacks are fenced by existing render generations and canonical evidence checks. Repeated correction and A-to-B-to-A require new confirmation; old receipt identity never revives.

Clear files and result remains the full record reset. Cancel and same-case retry invalidate authority without silently discarding intentional same-case assertions. A canceled native reset remains conservative: authority is cleared even if control values are restored.

## Strict acceptance

Dedicated browser checks must exercise explicit correction from candidate and confirmed comparisons, changed finder selections, manual ID correction and ABA, source replacement, same-ID retry, pending source/billing reads with late success/rejection, repeated corrections and canceled reset. Existing full regression scripts must pass on the frozen current source. Source hashes, individual commands, exit status, browser error blocks, prescribed correction assertion IDs and a decoded recovered-case screenshot are required. Independent review must have no important open findings.

Local synthetic acceptance does not establish human intent/comprehension, native provider validity, financial authority, every scheduling interleaving or universal platform behavior.
