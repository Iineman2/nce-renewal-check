# Principle 2 expanded identity closure

## Contract and implementation

Identity must remain the same from validation through display and confirmation. The selected comparison projection is captured once through its own property descriptor. Accessors are rejected without invoking them. Existing frozenData captures the three supplied string identifiers and rejects nested accessors, exotic/cyclic data, omissions, extra keys and unsupported lengths. Empty/unusable raw identifiers can remain honest link-review evidence; they cannot produce complete identity keys.

All selected-ID validation and rendering uses only the frozen captured object. It is checked against privately owned canonical source identity and the canonical claim trail. Repeated decision.selected reads are displaced. Later alias mutation or proxy value reads cannot substitute another record. A proxy can influence reflection; this boundary promises a captured consistent snapshot, not universal detection of a malicious runtime. Blocked/error decisions cannot display selected-record metadata.

Supplied account/customer/subscription keys, separate renewal occurrence, descriptive-label separation, missing namespace, reserved-account vocabulary and duplicate-account ambiguity retain their existing owners and boundaries. Authentic tenant identity and native mapping remain external. No new matching/search/confirmation authority or provider writes were added.

## Added gates

Six new model tests cover root/nested getter rejection with zero invocations, descriptor-read-once behavior and detached mutation, exact selected shape, serialization loss/coercion/authority, confirmation changes across account/customer/date/descriptive facts, normalization and a maximum 5,000-row/64-column fixture with optional identity columns through all four parser passes.

The new isolated browser script covers root/nested getters, selected extras/numbers/cycles, blocked-stage selected metadata, descriptor drift and queued alias mutation both before and after confirmation. Rejected shapes cannot offer confirmation. Consistent captured proxy snapshots retain original IDs. It also tests known-to-unknown account replacement and old confirmation invalidation, with zero page errors. Earlier identity, lifecycle, accessibility, source-consistency, reset/cancel, policy and concurrency suites remain required.

Confirmation basis is semantic selected-source data. Relevant account, customer, date and descriptor changes invalidate it. Row order and unrelated metadata alone do not establish a different logical record or semantic confirmation basis. The browser separately binds the File objects/current controls; a replacement file requires a new check. These are not authenticated source-version attestations.

## Remaining boundaries

The supported normalized format uses exact case/Unicode distinctions and trim normalization. Authentic identifier semantics, reused/migrated source IDs, native field mapping, cross-system account/customer/document linkage, operator comprehension and actual screen-reader tasks need independent evidence. No global workspace deduplication or authentication follows from a supplied tuple. Arbitrary hostile scripts/platform faults, continuous silent-mutation monitoring, low-memory/device-wide performance and future consumer/persistence/version migrations remain bounded or unqualified.

Four shared-parser passes remain within existing 2MB/5,000-row/64-column limits; optional fields and raw values retain parser limits. The maximal combined fixture is a model gate, not a universal timing SLA. Earlier qualifications remain historical after source changes.
