# Principle 6: Confirmation applies to a specific evidence state

## Expected behavior

A unique complete source case begins as a candidate. An explicit source or joint attestation confirms only its exact decoded CSV and exact selector. Confirmation is ephemeral, self-attested and unauthenticated.

Every invalidation irreversibly revokes the current receipt before clearing the selected case, link confirmation and derived comparison. Returning to previous bytes or a previous ID cannot revive that receipt. Reselecting any File object, even with identical bytes/name/metadata, is a new UI evidence generation. A new valid source case requires a fresh attestation.

Every confirmation and downstream interaction checks current controls, files, discovery state, displayed case evidence, policy and local calendar. The Current case region must retain its node, root visibility/semantic attributes, descendants and content; opening/closing its evidence inspector, root focus tabindex and root letter spacing, word spacing and line height do not change material evidence. Those three accessibility spacing properties survive rerendering; other root visibility/semantic changes invalidate authority. Silent changes stop on the next guarded action, focus, visibility return or periodic freshness check. Trusted-script changes followed by a full restoration between checks are outside browser-observable guarantees.

Record correction, source/billing replacement, cancel, reset, reload/history return, calendar/policy expiry and failures must never reuse old authority. A comparison failure revokes confirmation and clears the comparison; intact canonical source evidence remains inspectable as an unconfirmed candidate. Corrupt or stale source evidence clears the subject. Ordinary unchanged inspector toggles and focus must retain valid confirmation. No source confirmation alone establishes eligibility, cross-system linkage, financial coverage or permission to act.

## Version and lifetime boundaries

Model source version means exact decoded text, including raw lexical evidence and unrelated records. The API caller must revoke an attestation when its owning evidence session is replaced; the app does this centrally. File object/generation distinguishes equal-content replacement at the UI boundary. There is no authenticated native source revision, persistence or server-side freshness claim.

## Strict local gates

Dedicated model tests cover exact lexical and semantic source changes, selector binding, forged/cloned tokens, independent receipts, irreversible revocation, stale projection rejection and fresh recovery. Dedicated browser tests cover explicit/joint attestation, equal-content and changed-content replacements, ABA recovery, detached callbacks, altered evidence, native selector fallback events, inspector stability, focus and date expiry, reset and downstream clearing. Full prior unit/browser regressions run against the current captured source; earlier receipts remain historical.

Acceptance requires source and receipt hashes, full command inventories, completed prescribed assertion ownership, exact-reason negative checks and independent final review. Real native/provider authenticity, human comprehension and universal cross-browser/device acceptance remain pending.
