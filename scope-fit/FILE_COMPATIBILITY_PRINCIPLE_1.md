Compatibility means: **this reader can completely parse this supplied text under this normalized role profile for this named operation**. It establishes no source authenticity, native vendor format, case confirmation, business eligibility, agreement coverage or financial authority.

The current support owner is `file-support.mjs`. It declares policy `file-support-v2`, reader `normalized-csv-v2`, UTF-8 with an optional initial BOM, comma delimiters, double-quoted fields with doubled-quote escaping, multiline quoted fields and LF/CRLF/CR record endings. Headers are trimmed and lowercased; names must be unique and nonempty. Data values are trimmed while existing raw evidence is preserved. Completely empty decoded-cell records are skipped before trimming, including short empty records; whitespace-only records are retained and may have unresolved business facts. At least one data record is required; every retained record must match the header width. Leading BOM/header-edge normalization is permissive; internal required-header characters are preserved and cannot silently acquire a different name.

Two normalized profiles are enabled: Pax8 records for case discovery or record comparison; HaloPSA records for record comparison. Profile recognition depends on actual required columns and a complete parse, never a filename or MIME label. Case-sensitive values and business facts remain the existing case/decision owners' responsibility. A readable unfamiliar CSV is an unsupported profile requiring a corrected normalized copy; generic mapping is unavailable. Rename does not repair wrong content. Valid supported content is accepted even with absent or misleading filename/MIME metadata.

XLSX, PDF, DOCX, OCR, native Pax8/HaloPSA export profiles and generic mapping are unavailable. CSV limits remain 2,000,000 original bytes and decoded UTF-8 bytes, 5,000 data records, 64 columns, 64 UTF-16 code units per header name and 1,024 UTF-16 code units per cell. A file read uses one 30-second deadline. This principle publishes and consumes existing limits; full resource/cancellation qualification belongs to principle 3.

`runtime.mjs` requires the byte/text/decoder/encoder/form/timer/monotonic-clock APIs, derives the canonical source from the qualified role and rejects conflicting caller labels before file access. It schedules paired reads with attached handlers, checks actual size with the intrinsic ArrayBuffer getter (including genuine foreign-realm buffers), validates fatal UTF-8 behavior and original bytes, checks equality with File.text, then asks the sole CSV parser to validate the requested profile/operation. Legitimate U+FFFD is accepted and can be searched literally in query/customer/product filters; account and business identifier rules remain strict. UTF-16 BOMs get a specific UTF-8-copy repair; alternating ASCII/NUL bytes get a bounded "appears to use UTF-16" inference only after profile failure. ASCII byte validity cannot prove the original encoder. IO, representation, encoding and profile failures have distinct source-specific repairs; missing/broken APIs produce a technical reload stop. No permissive decoding fallback exists. Direct decoded-text model functions cannot attest original byte encoding.

The declaration's text and record guidance are projected canonically and checked for unique current nodes, exact tags/parents/content, declared attributes, reader limits, picker settings and visibility. The disclosure contains exactly its native summary and its contract; added claims, CSS-generated text and accessible-name/role overrides cannot bypass the visible contract. Early/halted guards still cancel native form submission. Cleanup bypasses the failing guard, and genuine page initialization is required for recovery. The unrestricted native picker permits selecting misnamed files; admission still depends solely on actual content. This does not qualify every OS/device picker.

Elapsed monotonic time is checked after reading, decoding and parsing before success. This prevents successful synchronous deadline overrun; a timer still cannot preempt synchronous work or abort already-started native promises. Full resource/preemption/cancellation qualification remains principle 3. A fully compromised host can forge all observations; the controlled guards do not claim immunity to that environment.
