# Feature 1.3 Principle 4: file contents remain data

Expected behavior defined 6 October 2026. This contract covers the enabled local normalized Pax8/HaloPSA UTF-8 CSV reader. Implementation and current acceptance evidence belong to `../output/file-compatibility-principle-4/REPORT.md`; this specification alone is not a pass.

## Exact boundary

Selecting a file authorizes acquisition and interpretation of its data under the application's fixed CSV grammar and typed business rules. It does not authorize executing supplied text, following supplied links, accepting supplied instructions, changing policy, choosing an operation or creating a case confirmation. A readable source is not authenticated or financially actionable.

1. Every formula, expression, macro description, script, HTML/XML fragment, URL, path and natural-language instruction remains a string. No expression evaluator, spreadsheet engine, browser markup parser, document renderer, macro engine, shell or model instruction consumer is invoked on it. Formula prefixes `=`, `+`, `-` and `@` are not globally censored: valid opaque identifiers and ordinary descriptions retain them. Invalid dates, enums and business facts take their existing typed unknown/repair routes.
2. The sole CSV lexer owns quoting, delimiters, line endings and source coordinates. Raw values, lexemes and original bytes remain recoverable. Display escaping is a separately identifiable presentation; it does not sanitize, rewrite, remove or replace original evidence. Leading whitespace, BOMs, multiline fields and encoded-looking text receive no second interpretation.
3. The declared role, operation, reader, policy, worker URL and required columns belong to application code. Additional headers such as `__proto__`, `constructor`, `then`, `policyVersion`, `operation`, `confirmed`, `actionAuthorized`, `financialVerdict` and `nextAction` are own data properties. They cannot set prototypes, run callbacks, alter policy or issue private capabilities. Recognized business fields may affect provisional domain conclusions through fixed typed parsers; this is their intended data meaning.
4. A file cannot choose a subscription, confirm a case, establish a cross-file link, accept a conflict, change optional user facts, restore superseded authority, navigate the page, invoke an external action or grant financial permission. Those transitions retain their existing user-action and private-issuance owners. Discovery may start after the authorized file selection; discovery does not confirm its candidates.
5. Filenames, MIME labels, headers, cells, source text, diagnostics, finder options and provenance reach text nodes or inert value/data attributes only. None becomes HTML, CSS, an event handler, a script/module URL, a link destination, form action, worker message command or generated program. Read-only DOM serialization is permitted for integrity comparisons; serialized evidence is never parsed back as markup.
6. Reading, discovery, checking and inspection cannot produce content-derived network requests, navigation, popups, dialogs, storage writes or downloads. Trusted application assets and the fixed local module worker may load. No remote fallback or uploaded file is enabled.
7. An explicit Save original action may recover every original byte, including hostile text, as a generated role/digest `.bin` download with `application/octet-stream`. It uses a locally created blob URL and revokes it, never a supplied name, MIME, path or URL. Recovery is not an active preview, a formula-safe spreadsheet export or a guarantee about another program opening the saved bytes.
8. Unsupported workbook/macro/archive/PDF/DOCX content never activates another reader. A valid normalized CSV named `.xlsm`, `.html` or `.pdf` remains CSV data if its actual content satisfies the current contract. A container signature does not select a format or bypass CSV/profile checks.
9. Handling, profile, transport, original custody and current-job checks finish before their dependent operation can publish. A forged completion, foreign/cloned receipt, wrong role/operation, malformed source or technical failure cannot establish success. Cancellation/replacement/removal invalidate affected work before late publication. Independent readable originals retain their existing inspection boundary.
   The main custody owner now reacquires the selected native Blob occurrence using a captured platform method and compares every admitted byte with the Worker bytes before publishing a handle. Coherent alternate bytes/text/hash cannot substitute another same-sized file. This comparison uses bounded yields and the existing current-job deadline and reservation; an unstoppable pending native read remains reserved after cancellation until it settles. The comparison proves identity to the supplied occurrence, not vendor authenticity or peak memory consumption. Worker input-error prose never becomes owned repair guidance.
10. A browser Content Security Policy is installed before application resources. It blocks inline scripts/handlers, string evaluation, connections, objects, frames, supplied base URLs and native form submission. Same-origin static modules/workers/fonts/images and existing application-owned inline styles remain permitted. This is a second barrier; text-only construction remains the primary boundary. The document policy is not represented as a Worker-response sandbox or a guarantee against arbitrary already-trusted script replacement.

## Strict acceptance gates

| Gate | Required witness |
| --- | --- |
| Literal preservation | Formula/DDE/external-reference, script/event/SVG/HTML/XML/CSS, URI/path and instruction corpus retains exact raw strings/lexemes and source coordinates, including quoting/BOM/control/multiline forms. |
| Typed interpretation | Executable-looking dates/enums do not evaluate to valid facts; formula-like valid opaque IDs remain usable only through the normal explicit confirmation path. |
| Authority invariance | Adding/reordering extra authority-named and reserved headers preserves the application's policy, typed action, selected subject and confirmation requirements; original evidence retains all extra columns. |
| Real browser acquisition | Hostile files pass through a genuine native module Worker and the current receiver before literal finder/original/subject/result displays are assessed. No mocked success packet establishes this gate. |
| No activation or side effects | Browser observes requests/attempts, navigation, dialogs, popups, downloads, storage and executable nodes/attributes; accepted and rejected sources produce no content-driven effects. |
| Browser policy enforcement | Actual browser probes confirm inline script/handler, eval/Function/string timer, remote load/connection, object/frame/base/form restrictions. Valid modules, CSS/fonts/logo, native CSV reading and explicit original saving still work. |
| Original recovery | Both roles' clicked downloads match every input byte/hash, use the generated `.bin` name and octet-stream MIME, and release their local blob URLs. There is no download before the click. |
| Failure/lifecycle | Unsupported content, wrong role, malformed final records, replacement/reset and forged transport cannot create current success or consume source instructions. |
| Detector qualification | Deliberately unsafe rendering, source-derived requests/navigation, premature downloads and forged authority are detected with cause-specific failures. Canary execution is demonstrated in a controlled test context. Suppressing/aborting network effects cannot hide attempted requests. |
| Regression and evidence | Full model suite, current relevant browser regression suites, automated accessibility, syntax, source-bound receipts, exact artifact hashes, preservation of historical proofs and independent correctness/maintainability/verification reviews. |

Qualification is finite local synthetic normalized CSV. New rich-text/remote/model/document/spreadsheet readers must independently attach to this boundary before enablement. This does not certify vendor authenticity, arbitrary browser/OS environments, compromised trusted code, manual assistive-technology use or third-party handling of recovered originals.

The current closure proof is owned by `output/file-compatibility-principle-4-closure`. The historical P4 pack qualifies its retained source snapshot. Current QC uses a shared pure classifier for browser checks and offline replay; complete observation snapshots, positive safe native identifiers, duplicate-key/ambiguous-receipt rejection and an externally supplied seal identity are required. Detector instrumentation records attempted construction before ancestry can be removed and records Worker effects independently of a terminal packet. Trusted application event functions and a single native clicked original recovery remain explicit permitted code paths.

Platform behavior references: [native Blob arrayBuffer promises](https://developer.mozilla.org/en-US/docs/Web/API/Blob/arrayBuffer), [MutationObserver removed-subtree delivery](https://developer.mozilla.org/en-US/docs/Web/API/MutationObserver/observe), and [CSP policy scope](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy). These explain platform limits; actual closure acceptance requires the retained current browser witnesses.
