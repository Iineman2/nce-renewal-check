# Principle 7 audit closure

**Intent:** Prevent corrected draft answers from migrating to another draft, and qualify the resulting evidence strictly.
**Current Behavior:** First correction clears assertion provenance; answers entered before parsing the next case can survive another change.
**Expected Outcome:** After a source case has existed, every explicit term/agreement edit owns only the current draft ID/File. Draft provenance never establishes canonical identity. Truly initial missing-file/no-match repair remains unbound; same-case retries retain answers. Existing central invalidation remains the sole receipt/read/result teardown owner.
**Truth Owner:** app.mjs owns draft assertion provenance and invalidation; preflight.mjs owns canonical identity and receipt authority.
**Cutover:** Replace the provenance gap in existing handlers; no parallel selection store.
**Acceptance Evidence:** Expanded owned browser scenarios, full current frozen unit/syntax/browser suite, decoded recovery screenshot, executed negative command/start/end receipt, exact-reason malformed checks, independent POST/FINAL review, all370 audit conditions explicitly mapped without universal claims.
**Evidence Lane:** Local synthetic qualification; native providers, human intent, universal devices and hostile runtime remain external/trusted boundaries.
**Kill Criteria:** Any cross-draft assertion carryover, stale callback ownership, important regression/review defect or fabricated review evidence blocks acceptance.
**Forbidden:** Deploy/provider mutations, overwriting old proof, claiming370 exact tests without evidence.
**Plan Review Gate:** Independent PRE before implementation; main implements sequentially, independent read-only POST and FINAL reviews.
