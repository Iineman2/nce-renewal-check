# Inert File Evidence Implementation Plan

**Intent:** Implement Feature1.3 Principle4: file contents remain data, preserving original evidence and the existing minimal control/information UX.
**Current Behavior:** Fixed local CSV readers, text-only source displays and private authority owners already provide the main boundary; browser CSP and consolidated adversarial acceptance are absent.
**Expected Outcome:** The exact contract in `scope-fit/FILE_COMPATIBILITY_PRINCIPLE_4.md` is implemented and qualified for current normalized CSV. Hostile-looking values remain literal, preserved data and cannot execute or grant authority.
**Target-Perspective Output:** An operator can select, inspect and explicitly recover hostile-looking valid CSV without source-driven execution, actions or confirmation; invalid source contents produce owned recovery, never alternate reader execution.
**Truth Owner:** `file-support.mjs` owns allowed CSV handling; `index.html` owns early document CSP; the sole lexer and private runtime/custody/case owners retain their existing responsibilities.
**Contract Boundary:** Native File -> fixed Worker/CSV lexer -> independently verified current packet/custody -> typed domain interpreters -> text-only views. Recovery crosses only into an explicit opaque original download.
**Cutover:** Install an early restrictive document CSP and publish the inert-data contract in FILE_SUPPORT. Retain the sole CSV/read/render paths and add direct hostile-input qualification.
**Displaced Path:** The unprotected document capability surface is restricted. No new parser/sanitizer/evaluator or alternate flow replaces existing data owners.
**Value Density:** Prevent execution if a later unsafe sink is introduced, and prove literal data/authority isolation through the actual native browser flow.
**Acceptance Evidence:** Hostile corpus model witnesses, actual native-worker browser read/display/recovery with side-effect inventory, cause-specific negative controls, full models/relevant current regressions/accessibility/syntax and source/artifact/historical identity checks.
**Evidence Lane:** Finite foreground local Chromium synthetic normalized CSV; no production/vendor/new-format/host compromise qualification.
**Kill Criteria:** No content-driven eval, markup parsing, auto-link/action, formula rewriting, authority-column merge, reader activation, upload, broad DOM redesign or proof overwrite. Fix every concrete gate failure before claiming acceptance.
**Architecture Slice:** Product edits limited to current declaration/document defense and any actual owner defect found by gates. New contract/tests/browser script and a new output owner record the evidence.
**Plan Review Gate:** Requires PRE review before execution.
