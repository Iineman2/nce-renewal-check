# File compatibility: explicit qualified support implementation plan

**Intent:** Implement feature 1.3 principle 1 against the existing local CSV capability.
**Current Behavior:** Parser limits, schemas and UI claims are separate literals; the reader rejects every U+FFFD and does not validate original UTF-8 bytes. Filename/type do not currently select another parser.
**Expected Outcome:** One immutable versioned declaration owns the enabled CSV reader, role-specific normalized profiles, operations, dialect, encoding, limits and explicitly unavailable capabilities. Every file read validates actual UTF-8 bytes and the requested normalized profile before the existing finder/comparison consumes it. Metadata never establishes compatibility. Readability remains distinct from vendor origin and business eligibility.
**Target-Perspective Output:** Before choosing files an operator can inspect exact current support, required columns, permitted operations and the supported repair route. Incorrect encodings, schemas and unsupported container contents return a file-specific repair without an eligibility verdict. Correct CSV works independently of filename/MIME metadata.
**Truth Owner:** file-support.mjs owns capability declarations; preflight.mjs remains the only CSV parser and existing case/receipt owner; runtime.mjs owns byte admission/decoding. app.mjs renders the declaration and retains existing lifecycle owners.
**Contract Boundary:** Local UTF-8 normalized comma-separated text; two qualified role profiles; finder and record comparison only. No native vendor profiles, generic mapping, XLSX/PDF/DOCX/OCR readers, authenticity, completeness of original exports, hosted handling or business/financial authority.
**Cutover:** Parser/runtime/UI consume the shared declaration. Replace hardcoded schema/support copy. Strict byte decoding replaces replacement-character heuristics. Current acceptance moves to a new source-bound principle pack with the previous feature acceptance retained as historical.
**Displaced Path:** Duplicate column/limit literals and the U+FFFD heuristic are removed. No alternative parser, receipt store or fallback reader.
**Value Density:** Close misleading qualification and encoding gaps without implementing future principles or file readers.
**Acceptance Evidence:** Independent PRE; exact new model contracts for catalog immutability, wrong operations/roles, metadata spoofing, UTF-8/BOM/replacement characters, wrong schema/dialect/containers, limits/timeouts and recovery; browser-visible declared support, positive finder/comparison and negative/recovery paths; complete prior model/syntax/43 browser regressions plus new script; fixed gate manifest; original proof bytes preserved; passing-baseline evidence negatives; actual correctness/maintainability/POST/FINAL reviews.
**Evidence Lane:** Local synthetic fixtures and isolated browser faults. Qualification is PASS_WITHIN_SUPPORTED_LOCAL_CONTRACT, never universal or real-provider acceptance.
**Kill Criteria:** Unavailable reader/profile advertised or enabled; metadata grants support; any bypass of required profile/operation; encoding silently repaired; changed historical proof; source drift after capture; omitted/forged gate; important regression or open review blocker.
**Architecture Slice:** Create scope-fit/file-support.mjs, file-support.test.mjs, ui-file-support.js, FILE_COMPATIBILITY_PRINCIPLE_1.md; modify preflight.mjs, runtime.mjs, app.mjs, index.html, README.md.
