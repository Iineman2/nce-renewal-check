The File guide does not fully declare authorization/retention/removal. Pagehide only invalidates results and can retain selected originals/caches; reset/removal is behind guards and viewport checks. Selection/currentness and file custody exist, but there is no explicit revocable per-selection handling owner.

## Absolute expected behavior

1. Authorization is the exact current native File occurrence, role and local handling-policy version in one page session. Same names/digests, serialized receipts, a different tab or a previous selection never grant permission. A source value cannot broaden it.
2. Selection authorizes local finding (Pax8 only), checking supplied records and evidence inspection. Halo selection cannot authorize Pax8 finding. No permission means no UI worker admission or byte/derivative publication. Each processing yield/completion and original action checks current authorization through existing owners.
3. File contents/metadata/derivatives are never uploaded, sent to OCR/AI/scanners, logged or persisted by the application. Only fixed application assets/examples are fetched. No browser storage, caches, service worker, clipboard write or cross-tab data channel is used for evidence. Static asset requests do not carry selected source data.
4. Application retention is temporary and page-scoped while the selection remains current, including a hidden tab. Cancel stops the task but retains the selected source/inspection and retry permission. No automatic expiry is invented.
5. Replacing or reselecting a role revokes the old occurrence, cancels its pending work and releases that role's originals/derivatives; dependent results/confirmations are invalidated by their existing owners. The unchanged independent source remains inspectable. Same-object reselection is a new occurrence.
6. Reset/native form reset/removal, pagehide, reload/exit and persisted-page restoration revoke all selected permissions first, terminate work, clear native picker values, fields, filters, cache, originals, results and case bindings. Cleanup runs without guard/layout/runtime prerequisites and continues independent cleanup phases when presentation fails. Restoration does not silently authorize retained File inputs.
7. Revocation cannot be undone by late Worker/native-byte/crypto settlement or detached old controls. Pending noncancelable platform acquisition can remain reserved until settlement, without accessible evidence or renewed permission; this follows the existing bounded job owner. A failed native termination stays quarantined/halts admission; never report successful physical erasure.
8. Original saving is an explicit user operation within current permission and returns exact admitted bytes through an owned, short-lived, revoked opaque binary URL. App removal does not remove the user's source, downloads, browser/OS copies or backups. There is no hosted record/deletion request; no claimed hosted deletion confirmation.
9. The handling declaration is immutable, exact and inspectable before selection in the existing separate File guide. Changed/missing/foreign declarations fail closed before dependent processing; no new narrative on the controls page. Disabled remote/agreement/tenant paths stay unavailable.
