## Exact policy

Per source: input and decoded UTF-8 <=2,000,000 bytes; decoded text <=2,000,000 UTF-16 units before offsets allocation; <=5,000 data rows plus header; <=10,000 lexical CSV source records including blank records; <=65,536 total cells including skipped blanks/header and failure frontier; <=64 columns; <=64 normalized header units; <=1,024 raw decoded cell units; <=4,096 lexical units per field, including quotes/ignored trailing whitespace. Zero-length input remains input repair. Observed size must match admitted size. No prefix truncation is a complete result.

At most two active jobs, no implicit queue, <=4,000,000 admitted input bytes in flight, <=two retained source texts. Each job deadline <=30,000ms measured with monotonic clock from admission through custody publication. A source operation names its current role/profile/policy and exact File occurrence. Cancellation is idempotent and stops active Worker; returned evidence remains subject to existing lifecycle/custody owners.

Original preview: at most five records, but page width reduces record count so <=64 cells per source page; all rows remain pageable and exact bytes recoverable. Native DOM validation rejects excessive owned nodes/text and excessive global body/cover candidates before expensive style/range loops. Generic data-capture limits remain independent.

## PRE clarifications

The aggregate cell bound is 65,536, so the ordinary 5,000-row required 9-column Pax8 and 4-column Halo profiles remain admitted; wide optional-column combinations can exceed it. All applicable limits hold simultaneously. Input reservation is not peak resident memory: up to 4,000,000 bytes in flight and up to 4,000,000 retained original bytes are separate budgets; worker/browser/native defensive copies and derivative objects add bounded implementation overhead without a claimed resident-memory ceiling.

The native structured-clone packet has <=1,000,000 visited plain values, depth <=12 and <=16,000,000 aggregate string UTF-16 units, plus <=2,000,000 transferred original bytes. Shape limits are checked by the Worker before sending and by the main receiver before adoption. Transport cannot run a foreign recursive getter because native structured clone supplies plain data; a compromised Worker/runtime remains an explicit boundary. Reused immutable scan and parsed-row caches have at most two text keys. Capped TreeWalker checks occur before clone/serialization/bulk style/range validation: <=1,500 original-evidence elements, <=4,000,000 evidence text units, <=10,000 body elements and <=64 candidate opaque covers. No expensive DOM validation starts after one of those caps fails.

Historical F13P2-M32's 5,000x64 table intentionally exceeds the new aggregate budget. Its proof remains untouched; its current regression becomes an explicit partial/recoverable limit case, with a separate admitted maximum-shape fidelity check. Each enabled capability and resource policy version advances; tests must assert the new exact declaration, not remove assertions.

## PRE boundary corrections

A Worker packet is valid only for its live private job, exact native File occurrence, role, operation, qualified profile, policy/reader/resource versions and protocol/run ID. It is bounded and typed before entering byte custody. The public packet consumer accepts only a privately issued immutable packet; arbitrary objects/clones cannot register evidence or cache entries. The canonical lexical owner produces the scan and the existing preflight owner reconstructs normalized rows/raw-row/source-trace WeakMaps from it. No second parser/semantic interpreter is introduced.

Native Worker termination is required. If termination is missing or throws, the manager quarantines the job and its reservation, halts admission until reload, rejects publication and reports technical failure. Capacity is never released while termination is known to have failed. Ordinary successful termination clears timer/listeners and releases reservation exactly once. A malicious runtime that lies about a native termination remains the compromised-host boundary; no synthetic acknowledgment is called proof of OS termination.

A resource cache contains at most two entries keyed by exact text plus current role/profile/policy schema. Entries are immutable; an old release cannot delete a replacement entry. Native File occurrence/case selection and confirmation are rechecked independently and are never cached as authority. Parsed-row reuse is private to the preflight owner and limited to the current canonical profile column identities, using the bounded scan lifetime. Concurrent finder/comparison work has no third cache entry: fixed eviction applies and no hidden queue is added.

Source-record count means lexical CSV records (quoted newlines remain inside one record), including blank/skipped records; it does not mean physical newline count. A final record terminator does not create a phantom EOF record. Documentation and boundary oracles use this definition.

PRE depth correction: FILE_SUPPORT owns max DOM/ancestor depth 64. Early capped traversal records parent depths and rejects at 65 before cloning or any repeated ancestor/style/range loop. N-1/N/N+1 and deep-body negative fixtures exercise the guard.

Development clarification reviewed in correctness-resolution.md: cancellation/deadline immediately terminates the Worker and fences publication. A canceled native custody verification and a cooperatively yielding packet verification retain their two-job/input reservation until their async cleanup actually settles. Do not release known pending verification as though it stopped; WebCrypto has no cancellation API. Main packet copying now yields every2048 visited values and checks live/deadline before each chunk. Native platform crypto activity and physical erasure are outside the acceptance claim. This qualifies unconditional cleanup/release wording above, including kill criteria.

Development metadata guard: native File name <=16,384 UTF-16 units, media-type label <=1,024 units before Worker admission, with exact N-1/N/N+1 and original-byte preservation tests. This closes large metadata string/display expansion outside the input-byte budget. Existing 6,000-unit filename recovery remains admitted; original content and metadata are never overwritten.
